# 後端專案規則模板

此文件套用到明確指定的後端 repo；專案特有的資料庫版本、架構與政策由專案補充。

- 對照現有入口、服務、資料存取與測試後再改動；表名、欄位、API 與狀態轉換需有程式或實際資料證據。
- 合約涵蓋成功結果、拒絕原因、授權、錯誤碼與重試語意；影響 consumer 的變更連同 schema／OpenAPI 與 consumer 驗證。
- 寫入的競態、原子性、鎖定順序與失敗回滾要有明確策略。不要把應用層「先查再寫」誤認為資料庫保證。
- migrations 使用專案官方命令產生；保留已套用的 migration 身分。大型 DDL 評估資料量、metadata lock、部署次序與恢復方式。
- 資料庫整合驗證使用相容版本，確認測試確實執行而非跳過；in-memory mock 不代表真實 transaction／lock 行為。
- 金額、日期、NULL 與時區的處理沿用專案 domain contract，不自行新增商業規則。
- 批次作業分別回報主寫入、後處理與失敗。權限檢查失效需拒絕操作，避免以假資料繼續呈現。
