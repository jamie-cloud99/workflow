# workflow-review

1. 取得精確 head/base、需求與 review 範圍；stacked PR 同時看增量與最終整體結果。
2. 沿入口、授權、狀態、資料寫入及 consumer 追蹤行為；finding 必須有觸發情境、影響及檔案證據。
3. 區分確定問題、待驗證風險與政策選擇。不要把風格喜好或中間分支過渡狀態當作最終缺陷。
4. 使用者要求多角色獨立 review 時安排獨立 pass，否則依風險選擇角度。
5. 需要政策判斷時先用白話說明，每次確認一個未定事項；未授權發佈的留言維持草稿。
