# test(workflow): 加入 PR 交付行為評測

當你請 AI 幫忙提交修改並建立 PR，它可能把你留給其他工作的修改一起提交，或把舊版本通過的測試當成新版本已經通過。這次加入幾道模擬題，檢查 AI 寫出的做法是否會犯這些錯誤。

## 怎麼測

我們讓 AI 分別在有提供與沒有提供交付指引時，回答同樣的三道題目。每道題都給它一份假的工作區狀態，請它寫出接下來的做法或 PR 草稿。另一個 AI 依照事先列好的條件檢查答案，例如是否保留不屬於這次任務的修改。

## 結果代表什麼

有提供指引時，11 項評分條件全部通過；沒有提供時，通過 9 項。差異只在 PR 內文是否使用繁體中文，以及標題是否有指定的類型前綴。和交付安全有關的條件，兩組都通過。

每組每題只跑一次，不能據此說指引讓交付更安全。只有其中一次作答真的選用了交付指引，其餘只是可以選用。

## 驗證範圍

這次新增的是評測案例，不會在日常建立 PR 時多加一道步驟。模擬題只要求 AI 寫計畫或草稿，沒有真的提交、推送或操作 GitHub。

本機的 39 個單元測試與文件檢查通過。沒有提供這次修改的遠端測試、部署或實際操作驗收結果，因此不宣稱這些驗證已完成。完整草稿與評分報告留在本機。
